## Frontmatter and structure

`##` headings become the numbered table of contents in the sidebar, and `###`
headings nest underneath. Reading time and the contents list are derived from
this file at build time — there is nothing to keep in sync by hand.

<Lead>
  Wrap the opening paragraph in `<Lead>` for the larger type. One per post, at
  the very top, or leave it out entirely.
</Lead>

Ordinary markdown works as expected: **bold**, *italic*, `inline code`,
[links](https://github.com/MD-AZMAL), lists, and footnote markers<sup>1</sup>.
Internal links like [the projects page](/projects) stay client-side
automatically.

> A blockquote is styled as a pull quote — short, declarative, one idea.

## Code

Fenced blocks are highlighted at build time by Shiki, in a theme matched to the
site palette. No highlighting JavaScript is sent to the browser.

```ts title="contracts/transfer.ts"
export const transferFunds: ToolContract = {
  name: 'transfer_funds',
  input: z.object({ to: z.string().uuid(), amount: z.number().positive() }),
  effect: 'irreversible',        // read | write | irreversible
  retry: { max: 0 },             // never auto-retry
  requires: ['human_ack'],
}
```

The `title=` attribute is optional and renders a filename bar above the block.
Highlight specific lines with `{2,4-6}` after the language, and specific
substrings by wrapping them in `[[ ]]` — see the rehype-pretty-code docs.

## Callouts

<Callout tone="note">
  `note` is the default — a grey diamond. Use it for context the reader can skip.
</Callout>

<Callout tone="tip">
  `tip` has an orange outline. Use it for the thing you wish someone had told you.
</Callout>

<Callout tone="warn">
  `warn` is solid orange. Use it sparingly, for things that will actually bite.
</Callout>

## Comparisons and asides

<Compare>
  <Side kind="bad" label="before">
    The naive version, described honestly. Being fair to it is what makes the
    other column persuasive.
  </Side>
  <Side kind="good" label="after">
    What you changed, and the property that changed with it.
  </Side>
</Compare>

<Note>
  `<Note>` floats a margin note to the right on wide screens and folds inline on
  narrow ones. Good for a caveat you do not want interrupting the sentence.
</Note>

Regular paragraphs flow around the margin note, which is the point of it. Keep
notes short or they outrun the paragraph they belong to.

## Numbers

<Stats>
  <Stat value="3" label="effect classes" />
  <Stat value="1" label="place policy is enforced" tone="accent" />
  <Stat value="0" label="auto-retries on writes" />
  <Stat value="100%" label="of runs replayable" />
</Stats>

`<Stats>` renders a row of up to four cards, always neutral. `tone="accent"`
sets one figure in orange — use it on the number the post is about, not on
every card.

## Tables

Markdown tables pick up the article styling and scroll horizontally on small
screens. `<Chip>` gives you small neutral pills; `tone="o"` marks the one row
that matters.

| Effect | Meaning | Default retry | Needs ack |
| --- | --- | --- | --- |
| <Chip>read</Chip> | No observable change outside the runtime. | 3, exponential | No |
| <Chip>write</Chip> | Changes state another tool can undo. | 1, idempotent | Configurable |
| <Chip tone="o">irreversible</Chip> | Cannot be undone safely. | 0 | Always |

sharp at any size, theme-correct, and weigh nothing. Give each stroked element
`pathLength="1"` and it draws itself in as the figure scrolls into view.
